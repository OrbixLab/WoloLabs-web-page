Your first game

Paint the Board, step by step: put a piece on a cell and it lights up in the colour you picked. Built by talking, not coding.

12 min readBeginnerAtlas Studio 0.2
In this guide What we’re building Create the project Ask the agent Play it Fill in the game sheet Keep going Under the hood

01What we’re building

Paint the Board is about the smallest game that still uses everything Atlas has: the phone screen, the lights and the pieces.

  • The phone shows 8 colour buttons. You pick one.
  • You put any piece on any cell, and the cell lights up in that colour.
  • You lift the piece and the cell stays painted.

You’ll need Atlas Studio installed and an AI agent connected, both covered in guide 2. No Atlas 64 needed: everything happens in the Simulator.

02Create the project

  1. Add a project

    On the home screen, press Agregar proyecto (add project) → Nuevo juego (new game). In Empezar desde (start from), leave Juego vacío (empty game).

  2. Name it and pick the orientation

    Título (title): Paint the Board. The Identificador (identifier) fills itself in as paint-the-board: it’s the game’s folder and its name in the store. Orientación: Vertical (393×852). Press Crear (create).

  3. It opens in the Simulator

    A new game isn’t empty: it comes with a starter that already works. Press Ejecutar (run) and drag a piece from Fichas onto the board: the cell lights up while the piece is there and turns off when you take it away. We’ll change exactly that.

03Ask the agent

  1. Connect your agent

    In the WOLO IA chat, pick your agent and press Conectar. If it’s your first time, guide 2 walks you through it.

  2. Paste this message

    Describe the game the way you’d explain it to a friend: what’s on the screen, what happens on the board, and how you’ll know it works.

    Message for the agent

    Let’s make a game called Paint the Board, for one module. On the phone screen: the title, a small picture of the board, and 8 colour buttons (red, orange, yellow, green, cyan, blue, purple, white). The selected colour has a white border. On the board: when a piece is placed on a cell, that cell lights up in the selected colour. When the piece is lifted, the cell stays painted. A piece on a painted cell repaints it with the current colour. Use a brightness that stays visible even if the board is dimmed. When you’re done, test it in the Simulator: paint a few cells, lift the pieces, change colour, and tell me how it went.

  3. Let it work

    The agent reads the project, changes the game’s screen and logic, checks it against the platform rules, runs it in the Simulator, places pieces on its own to test it and then tells you what it did, in plain words. You’ll see the board and the phone change while it works.

If it doesn’t come out right

Don’t start over: say what’s wrong. “The colour buttons are too small”, “lifting the piece turns the cell off, it should stay”. If it’s something you can see, press Señalar and click it first.

04Play it

Now check it yourself, the way a player would:

  • Drag a piece from Fichas onto a cell. It lights up red, the first colour.
  • Drag the piece off the board, or right-click it. The cell stays red.
  • Click the blue button on the phone. Place a piece on the same cell: it turns blue.
  • Leave a piece sitting on a cell and paint around it. Pieces and paint live together.

Then paint something. The heart in the screenshot is 30 cells, about two minutes of placing and lifting.

05Fill in the game sheet

Everything the store will show about your game lives in the Ficha del Juego (game sheet), in the Panel de Control tab. It’s worth filling in now, while the idea is fresh:

  • Título and Versión (title, version): leave 0.1.0 until you publish.
  • Jugadores and Tableros (players, boards): 1 to 1 here. A game for bigger tables sets the minimum it needs and the maximum it uses.
  • Descripción and up to three categorías (description, categories), from the store’s list.
  • Portadas (covers): a vertical one of 320 × 440 and an optional landscape one. Studio puts a placeholder until you add yours.

Press Guardar (save). Nothing goes to the store yet; that happens in guide 6.

06Keep going

Each of these is one more message to the agent. Send one, try it, then the next.

Add a clear button

Add a “Clear” button under the colours that turns off every cell of the board.

Add an eraser

Add a ninth button, the eraser. With it selected, placing a piece on a cell turns that cell off.

Give it an ending

When all 64 cells are painted, show the end-of-game screen with how long it took, and let me play again.

That last one already makes it a game: a goal, a measure and a reason to try again. Next guide: how to let the agent test all of this for you.

07Under the hood

You don’t need to read this. But if you’re curious, this is the whole logic of Paint the Board, as it ended up. The screen (title, board mirror, buttons) lives in a separate scene file that Studio’s editor shows visually.

Show main.gd (70 lines)

Three things to notice: the palette of 16 colours sent to the board, the colour buttons calling _select, and _on_piece_placed, which paints the cell. There’s no code for lifting a piece: doing nothing is what keeps the cell painted.

extends Control

## Paint the Board
##
## Pick a colour on the screen; every piece placed on the board paints its cell with that colour.
## Lifting the piece leaves the cell painted.

## Palette index 0 is "off". Indexes 1-8 are the colours the player can pick.
const PALETTE_COLORS: Array[Color] = [
	Color(0.0, 0.0, 0.0),      # 0 off
	Color(0.90, 0.12, 0.10),   # 1 red
	Color(1.00, 0.45, 0.05),   # 2 orange
	Color(0.95, 0.73, 0.25),   # 3 yellow
	Color(0.25, 0.85, 0.20),   # 4 green
	Color(0.10, 0.80, 0.85),   # 5 cyan
	Color(0.15, 0.30, 0.95),   # 6 blue
	Color(0.65, 0.20, 0.90),   # 7 purple
	Color(1.00, 1.00, 1.00),   # 8 white
]
const COLOR_NAMES := ["", "Red", "Orange", "Yellow", "Green", "Cyan", "Blue", "Purple", "White"]
## Brightness 0-15. 8 or more stays visible even when the player dims the board.
const BRIGHT := 12

var _selected := 1

@onready var _status: Label = %Status
@onready var _swatches: GridContainer = %Swatches


func _ready() -> void:
	var palette: Array = PALETTE_COLORS.duplicate()
	palette.resize(16)
	for i in range(PALETTE_COLORS.size(), 16):
		palette[i] = Color.BLACK
	Atlas.board.set_palette(palette)

	for i in _swatches.get_child_count():
		var swatch: Button = _swatches.get_child(i)
		swatch.pressed.connect(_select.bind(i + 1))

	Atlas.pieces.placed.connect(_on_piece_placed)

	await Atlas.board.refresh_modules()
	Atlas.board.clear()
	_select(1)


func _select(index: int) -> void:
	_selected = index
	for i in _swatches.get_child_count():
		_style_swatch(_swatches.get_child(i), i + 1 == index, PALETTE_COLORS[i + 1])
	_show("Colour: %s. Place a piece on any cell." % COLOR_NAMES[index])


func _on_piece_placed(module: int, cell: Vector2i, _global_cell: Vector2i) -> void:
	Atlas.board.set_pixel(module, cell.x, cell.y, _selected, BRIGHT)
	_show("Painted %d,%d %s" % [cell.x, cell.y, COLOR_NAMES[_selected].to_lower()])


func _style_swatch(swatch: Button, selected: bool, color: Color) -> void:
	var box := StyleBoxFlat.new()
	box.bg_color = color
	box.set_corner_radius_all(14)
	box.set_border_width_all(4 if selected else 0)
	box.border_color = Atlas.ui.color(&"text")
	for state in ["normal", "hover", "pressed", "focus"]:
		swatch.add_theme_stylebox_override(state, box)


func _show(text: String) -> void:
	_status.text = text
	print(text)
